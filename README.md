# 机器学习 → AI 应用工程师 学习计划

> 背景：美国音乐科技硕士，数学偏弱，会一些 Python
> 目标：国内 AI 应用工程师岗位，以**音乐/音频 AI** 作为差异化方向
> 节奏：时间不限，9–12 个月做扎实

## 定位

- **主赛道**：AI 应用工程师（RAG / Agent / 评测 / 微调 / 部署）—— 市场最大
- **差异化**：所有项目都做在音乐/音频领域 —— 国内"懂音乐 + 懂 AI"的人极少
- **核心原则**：不跟 AI 比写代码，而是成为"能让 AI 系统在真实业务里稳定跑起来、并且能证明它好用"的人

## 路线图

| 阶段 | 时长 | 学什么 | 音乐版作品 | 状态 |
|---|---|---|---|---|
| 0 地基 | 6–8 周 | Python 工程化；ML 核心直觉；PyTorch 训练循环 | 从零训练音乐流派分类器 | 🔄 进行中 |
| 1 LLM 应用 | 3–4 周 | token、上下文、结构化输出、国产模型 API | 和弦/歌词分析小工具 | |
| 2 RAG | 5 周 | 分块、embedding、混合检索、重排、检索评测 | 音乐制作知识库问答（带准确率） | |
| 3 Agent | 5 周 | 工具调用、MCP、workflow vs agent、注入防护 | 音乐制作助手 Agent + MCP server | |
| 4 评测 ⭐ | 4 周 | LLM-as-judge、失败案例集、CI 评测、回归测试 | 给所有项目补评测流水线 | |
| 5 微调 | 4 周 | LoRA、量化、前后对比 | 微调 Qwen 或音频模型（MERT/CLAP） | |

| 7 毕业作品 | 6–8 周 | 把 2–6 串成完整产品 | 面向音乐人的 AI 工具 | |
| 8 求职 | 持续 | GitHub 整理、模拟面试、JD 分析 | 3 个项目 + 1 个毕业作品 | |

## 规则

1. 每个项目必须有：README（问题/方案/取舍）+ **评测数字** + 失败案例
2. AI 编程工具从第一天就用，但**每一行代码都要能解释**
3. 数学只学直觉，遇到哪里讲哪里；PyTorch 负责算导数
4. 模型以国产 API 为主（Qwen / DeepSeek / 豆包），顺带熟悉 Dify / Coze
